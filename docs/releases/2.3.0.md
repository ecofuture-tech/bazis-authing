# bazis-authing 2.3.0

Requires Bazis 2.3 (Django 6.1, FastAPI 0.142) and bazis-users 2.3.

## Security

- **Sign-in through Google could take over accounts.** A user was found by the email of the
  Google account without checking that Google verified it, and the profile of the
  userinfo endpoint (fetched with an access token sent by the client to
  `/google-auth-verify/`) overwrote the claims of the verified ID token. Now the email must
  be verified (`email_verified: true`), the ID token identifies the account, and the
  profile only completes the names if it belongs to the same account. Inactive users
  cannot sign in.
- Users created through Google get an unusable password instead of an empty one.
- Profile data and tracebacks are no longer printed to stdout; errors go to the
  `bazis.contrib.authing.*` loggers and the client receives a generic message.
- `python-jose` is replaced with `PyJWT`.

## Fixes

- **The sign-in through Google did not work**: the routes used the module `bazis.core.app`
  instead of the application, so building the redirect URLs failed. The redirect URI is
  `BAZIS_G_AUTH_REDIRECT_URI` if set (the setting was unused).
- `GET /auth/` failed with 401 for an invalid or expired token (e.g. a cookie signed with a
  previous `SECRET_KEY`), so the client could not get a new store token; such a token now
  means that the user is not authorized.
- Only the last error of the authorization store was kept.
- The JWT algorithms were passed as a string instead of a list.

## Dependencies

- `google-auth`, `google-auth-oauthlib` and `google-api-python-client` are removed: nothing
  uses them (the Google integration is built on authlib).
- `bazis>=2.3.0`, `bazis-users>=2.3.0`, `PyJWT>=2.10`, `authlib>=1.3`, `httpx>=0.27`.

CI runs the tests on Python 3.12–3.14 and with the lowest allowed dependency versions;
releases are made with the Release workflow (see `CLAUDE.md`).
